# Data (Track B)

Built by `scripts/build_pool.py` (pool, eval, downloads) and `scripts/build_cots.py` (R1 hard set), both Modal jobs
(`uv run --env-file .env modal run scripts/build_pool.py::main --step {download|weights|pool}`,
`modal run scripts/build_cots.py::cots`, `modal run scripts/build_pool.py::pull`). Loader: `cpp/problems.py`
(`load_pool`, `full_tests`). The old-plan pipeline (P1/P2 pools, teacher trajectories, `build_p1.py`) was removed.

## Record schema (pool.jsonl, eval150.jsonl)

`{id, title, statement, rating, tags, time_limit (s), memory_limit (MB), sample_tests:[{input,output}],
full_tests:{path,n,n_official,n_generated}, checker, checker_lang, checker_max_score, year, contest_id}`

- `full_tests.path` is the in-volume path (`/vol/pool/tests/570_B.json` when `cpp-data` is mounted at `/vol`);
  `cpp.problems.full_tests(p, vol_root=...)` remaps it. Tests are official (non-truncated, <400 chars) plus up to 30
  generated tests (15 largest inputs + 15 random), CRLF normalised to LF.
- `checker`: **Python source, not testlib C++.** open-r1's `generated_checker` is a `checker.py` run as
  `python checker.py input.txt correct_output.txt contestant_output.txt`; it prints a score. `null` means exact
  match (whitespace/token tolerant compare by the judge). `checker_lang` is `"python"` or `null`.
- Accept a checker result iff exit code 0 and last stdout token >= `checker_max_score` (1 for 307 checkers, 100 for 50).
  Scan of all 357 checkers (341 pool + 16 eval): none print partial credit; every printed value is 0 or the max, and
  each accepts the jury answer at max and scores empty / garbage / `-1` output as 0. No problems were dropped.
  Caveat: checkers crash (no score) on a few malformed outputs, treat exit != 0 as reject.
- Build-time check: every kept checker accepts the first full test's jury answer.

## R1 hard set (optional)

`codeforces-cots` card (`solutions_decontaminated`, 40,665 rows) says traces are generated by DeepSeek-R1; no OpenAI or
Anthropic. The card does not filter for correctness, so each trace must be verified in the sandbox before use.
Rows with rating >= 2200 (rating joined from `verifiable` train by id), finished with `stop`, `</think>` present, C++
block in the answer: 2,160 problems eligible, 364 of them in our pool. `r1_hard.jsonl` = 200, all in the pool, shortest
trace per problem (mean 12.6k tokens, mean rating 2566); `r1_hard_all.jsonl` = every eligible trace (shortest per
problem). Record: `{id, rating, tokens, thinking, code, in_pool}`; the plan restricts use to pool problems the model never
solves, so pick from `r1_hard_all.jsonl` after round 1 by `id`.

### R1 verification results (`scripts/build_r1.py`, Modal judge, 2026-11-14)

Each trace's C++ was judged on ALL full tests (Modal `tinker-cpp` judge; python checkers supported), required max test time <= 0.6 x limit,
a matching sample-1 run and passing samples. Drops (reasons by count):

| Candidate set | Cap | Judged | Kept | Drops |
| --- | --- | --- | --- | --- |
| `r1_hard.jsonl` (200) | 14k tokens | 115 | **39** | too_long 85, wrong_answer 72, slow 2, compile_error 2 |
| `r1_hard_all.jsonl` in pool (364) | 30k tokens | 364 | **67** | wrong_answer 281, compile_error 11, slow 3, sample_run_mismatch 1, OSError 1 |

Survivors (30k set): rating mix 2200-2399: 27, 2400-2599: 25, 2600-2799: 8, 2800+: 7 (mean 2437); mean trace 13.3k tokens (max 19.5k);
at a 14k cap 39 remain (mean 10.9k), at 16k 48. Pass rate falls with rating (27/93, 25/101, 8/67, 7/103) and with trace length
(34% of judged for the 200 shortest-per-problem set vs 18% overall). R1 traces are mostly wrong on these problems, which is why verification is mandatory.
Output files (gitignored): `data/pools/r1_hard_14k.jsonl` (39), `r1_hard_30k.jsonl` (67), plus `r1_*_full.jsonl` with the failures.

## Known gaps

- 754 of 1,500 pool problems (from older contests) have no generated tests, so only the official <400-char tests
  (>=5 required): weak against TLE and large-input bugs, a risk of false "passes". Prefer problems with
  `n_generated > 0` when selecting trajectories if round-1 data looks noisy; 204 of the 450 hard ones are in this group.
- Checkers were validated only on the jury answer, not on real wrong solutions.
- Eval rating mix is not the pool mix (heavy on hard, 59 problems 2200+), compare against baseline on the same set only.
- Pool test storage is 28 GB (large generated inputs, cap 8 MB per test); reading is fine, avoid copying it off the volume.
- Statements are `description` + Input/Output/Note sections with LaTeX `$$$` markers as in the dataset.
